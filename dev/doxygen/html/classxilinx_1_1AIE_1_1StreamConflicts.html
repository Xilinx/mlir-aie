bool StreamConflicts::conflict ( size_t s,
size_t t ) const

Whether s and t can deadlock if they share an arbiter or a link.

Streams from one source are serialized there anyway, and streams into one destination already wait on each other there, so neither conflicts. The packets one source sends with one id move down every branch as one, so the same holds for any two streams of such trees.

bool forcedWaits = false,

A cycle of waits the packet streams can deadlock in when routed along routes, indexed like getStreams(), that the routing of some requested stream takes part in; nullopt when there is none.

Waits between trees at the master port of a receiver they share hold however they are routed, so they count only with forcedWaits. With definite, drains that need StreamDeadlockAnalysis::assumptions do not count.

◆ unavoidable()

SmallVector< std::pair< size_t, size_t > > StreamConflicts::unavoidable ( ) const

The requested streams where the first can hold up the second however they are routed, as one source or receiver already orders them.

Only pairs with a packet stream count: circuits take no arbiter, so a wait between two of them is the design's, not a hazard of any routing. Nor do pairs that need StreamDeadlockAnalysis::assumptions: the routing cannot help those either, and the design may well not do what is assumed.
