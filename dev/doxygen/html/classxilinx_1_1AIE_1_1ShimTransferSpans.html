Detailed Description

Shim endpoint lifetimes, including calls to self-contained runtime sequences.

MM2S transfers conservatively remain live until their sequence returns; a callee's return and a dispatch boundary are themselves taken as the end of its sends, by the aiex.run and hardware-context contracts, not by anything this analysis computes. A receiving channel writes whatever arrives into the task it runs, so a receiving end shares only by explicit permission or where the array cannot send its words outside its turn: its senders wait on a gate the host fills only after the end before it is awaited, and each sequence drains all that gate lets them send.

xilinx::AIE::ShimTransferSpans::ShimTransferSpans ( DeviceOp device,
llvm::function_ref< std::optional< End >(mlir::StringAttr)> endOf,
std::optional< Gates > gates = std::nullopt,
bool plannedOverlay = false )

endOf maps a symbol a runtime sequence transfers through to the objectFIFO end it belongs to, or nothing when it belongs to none.

gates holds each receiving end's gates, keyed as endOf keys ends; without them, a receiving end shares only by explicit permission, which is all a caller running before the proofs can know. With plannedOverlay, the control overlay's channel on each column's shim tile is an end too, overlayEnd(), before aie-generate-column-control-overlay makes it: it carries the control packets to its column and every configuration load, as the overlay's own channel does once made.
